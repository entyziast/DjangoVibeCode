# Правила работы над проектом

## Назначение и стек

Проект — приложение для подготовки к экзамену. Планируемый стек: Django, PostgreSQL и Docker Compose для запуска приложения и базы данных.

## Сценарий работы и материалы

- Сначала пользователь видит список доступных экзаменов, выбирает экзамен и переходит на страницу подготовки.
- На странице подготовки показывается случайный вопрос выбранного экзамена. Готовый ответ раскрывается после нажатия кнопки.
- Храни экзамены, готовые вопросы и ответы в PostgreSQL. Выбирай вопросы только из материалов выбранного экзамена.
- Предусматривай несколько экзаменов, но на первом этапе единственный предмет — «Операционные системы».
- Источник начальных материалов — большой файл пользователя с готовыми вопросами и ответами по операционным системам. Не выдумывай его формат до изучения файла.
- Генерация вопросов и обращения к языковой модели во время работы приложения не требуются; не добавляй их.
- Если экзаменов или вопросов выбранного экзамена нет, показывай понятное пустое состояние без ошибки сервера.
- Основной сценарий — самостоятельная подготовка по готовым ответам, а не тестирование с автоматической оценкой и подсчётом баллов.

## Требования к разработке

- Старайся писать простой и понятый код, используя правильную архитектуру.
- Используй встроенную систему пользователей и аутентификации Django; не создавай собственную независимую систему пользователей.
- Сопровождай изменения моделей соответствующими миграциями Django.
- Выполняй выбор случайного вопроса на сервере и сохраняй соответствие между показываемым вопросом и раскрываемым ответом.
- Не добавляй пароли и ключи API в репозиторий. Передавай секреты через переменные окружения или другие внешние средства хранения секретов.
- Объясняй внесённые изменения и сообщай результаты выполненных проверок. Если проверки не запускались, явно указывай это и причину.
- Отвечай пользователю по-русски.
- Не добавляй команды запуска, пока они не реализованы.

## Ревью кода

- При запросе на ревью кода проекта используй навык `django-review`, описанный в `.opencode/skills/django-review/SKILL.md`.
- Во время ревью не изменяй файлы. Сообщай замечания и предлагаемые исправления разработчику в чате.
- Отсутствующие части приложения отмечай как непроверенные и перечисляй в чате; не реализуй их в рамках ревью.
