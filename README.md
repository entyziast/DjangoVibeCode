# Подготовка к экзаменам

Локальное учебное приложение на Django 5.2 LTS, PostgreSQL 17 и Docker Compose.
Интерфейс — Django templates, HTML и CSS. В первой версии доступен предмет
**«Операционные системы»** и 20 подготовленных карточек из `data/questions.json`.
Во время работы сайта языковые модели и внешние API не используются.

## Возможности

- Главная страница со списком предметов, темами и вопросами на странице подготовки.
- Случайный вопрос выбранного предмета; ответ скрыт до нажатия «Показать ответ».
- Раскрытие ответа не делает запрос к серверу и не меняет вопрос.
- «Следующий вопрос» выбирается на сервере и отличается от текущего, если есть
  другие карточки. Повторы более ранних вопросов возможны.
- Если карточка одна, она открывается снова со скрытым ответом. Если карточек
  или предметов нет, показывается понятное сообщение.
- Для подготовки не нужны регистрация и вход. Админка использует встроенных
  пользователей Django; личного кабинета и статистики нет.

## Требования

Нужны Docker с запущенным движком и Docker Compose V2 (`docker compose`). На Windows
подойдёт Docker Desktop в режиме Linux-контейнеров. Локально устанавливать Python
и PostgreSQL не требуется. Команды выполняются **из корня проекта**.

Это конфигурация для локальной лабораторной работы, не для публикации в Интернете:
используется сервер разработки Django с `DJANGO_DEBUG=1`, который также раздаёт CSS.
Порт опубликован только на `127.0.0.1`. Для промышленного развёртывания нужны отдельные
настройки HTTPS, сервера приложения, статических файлов и безопасности.

## Первый запуск

### 1. Настройте окружение

PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux/macOS:

```sh
cp .env.example .env
```

Если `.env` уже есть, не перезаписывайте его: дополните недостающие настройки вручную.
Откройте `.env` в редакторе и заполните:

- `DJANGO_SECRET_KEY` — длинным случайным значением (не менее 50 символов);
- `POSTGRES_PASSWORD` — отдельным случайным паролем базы данных.

Для генерации первого значения можно выполнить:

```sh
docker run --rm python:3.13-slim python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Выполните команду ещё раз для отдельного пароля PostgreSQL. Перенесите полученные
значения в соответствующие строки `.env`; не используйте одно значение дважды.
Сам `.env` исключён из Git и образа Docker. Без заполненных секретов Compose
откажется выполнять команды. Пароль администратора не задаётся через этот файл.

### 2. Соберите образ и подготовьте базу

```sh
docker compose build web
docker compose up -d db
docker compose run --rm web python manage.py migrate
```

Compose ждёт успешного `pg_isready` перед запуском контейнера `web`, включая
одноразовые команды `run`. Миграции создают таблицы и предмет «Операционные системы».
Сами карточки миграции не импортируют. Выполняйте команды последовательно;
при ошибке сначала устраните её, не переходя к следующему шагу.

### 3. Импортируйте готовые карточки

```sh
docker compose run --rm web python manage.py import_cards data/questions.json
```

Для первого импорта ожидается: `Создано: 20; обновлено: 0; всего обработано: 20`.
При повторном импорте того же файла: `Создано: 0; обновлено: 20; всего обработано: 20`.

### 4. Запустите сайт

```sh
docker compose up -d web
```

Приложение: **http://localhost:8000/**

Выберите «Операционные системы», обдумайте вопрос и раскройте ответ. При переходе
к следующему вопросу ответ снова закрывается. Обновление страницы карточки не
выбирает новый вопрос: каждая карточка имеет постоянный адрес.

Если порт 8000 занят, измените `WEB_PORT` в `.env`, повторите `docker compose up -d web`
и используйте соответствующий порт в браузере.

## Администратор

Создание администратора — необязательный шаг для подготовки:

```sh
docker compose run --rm web python manage.py createsuperuser
```

Команда интерактивно запросит имя, почту и пароль. Админка:
**http://localhost:8000/admin/**. В ней можно управлять предметами и карточками.
Идентификатор сохранённой карточки в админке доступен только для чтения.
Удаление предмета с карточками защищено от случайной потери материалов.

## Формат и правила импорта

`data/questions.json` — непустой JSON-массив в UTF-8. У каждой записи ровно пять полей:

| Поле | Требование |
| --- | --- |
| `id` | Глобально уникальная непустая строка до 64 символов: строчные латинские буквы, цифры, одиночные дефисы между группами, например `os-001` |
| `topic` | Непустая строка до 255 символов |
| `question` | Непустая строка с вопросом |
| `answer` | Непустая строка с ответом |
| `source_ref` | Непустая строка с указанием места в источнике |

Проверяются типы, наличие и состав полей, ограничения моделей, повторяющиеся
ключи JSON, повторяющиеся ID, некорректный Unicode и нулевые символы. Весь файл
проверяется **до записи**, затем вся партия сохраняется в одной транзакции.
Ошибка базы откатывает изменения партии. Существующие записи обновляются по `id`,
новые создаются. Карточки, отсутствующие в файле, не удаляются. Содержимое строк
не обрезается и не переформулируется. Проверка фактов и смысловых дубликатов
не входит в команду импорта.

По умолчанию используется предмет с адресом `operating-systems`. Для другого
предмета сначала создайте его в админке и передайте его адрес:

```sh
docker compose run --rm web python manage.py import_cards data/questions.json --subject another-subject
```

Этот пример требует отдельного подходящего набора: команда не перенесёт уже
существующие ID из одного предмета в другой. Для разных предметов используйте
разные ID.

Файл `data/questions.json` подключён в контейнер только для чтения. После его
изменения на компьютере повторите команду импорта; пересборка образа не нужна.
Редактирование файла само по себе не меняет базу. Если файл заменён редактором
и контейнер не видит новую версию, выполните импорт через новый контейнер `run`,
как в примерах выше.

Переносы строк в JSON записываются как `\n`. В базе и при показе ответа они
сохраняются. Шаблоны автоматически экранируют текст, CSS сохраняет переносы:
HTML из вопроса, ответа или ссылки на источник отображается как текст и не исполняется.
Ссылка на источник — справочная подпись; PDF для работы сайта не требуется.

## Проверки

Следующие команды можно выполнить самостоятельно после настройки окружения:

```sh
docker compose config --quiet
docker compose run --rm web python manage.py check --database default
docker compose run --rm web python manage.py makemigrations --check --dry-run
docker compose run --rm web python manage.py showmigrations
```

Первая проверяет Compose, вторая — настройки Django, третья — отсутствие изменений
моделей без миграций (не создаёт файлы), последняя показывает применённые миграции.
Это не автоматические функциональные тесты. Тесты в этой версии не добавлялись
по условию задания.

Для ручной проверки интерфейса: убедитесь, что до нажатия ответ закрыт, после нажатия
вопрос остаётся прежним, а «Следующий вопрос» меняет ID и закрывает ответ. Пустое
состояние предмета можно увидеть после миграций, но до первого импорта, либо создав
отдельный предмет без карточек. Не удаляйте рабочие материалы ради проверки.

## Последующие запуски и изменения кода

Обычный повторный запуск:

```sh
docker compose up -d
```

После изменения кода или зависимостей пересоберите образ. После изменения моделей
разработчик должен создать и сохранить миграции; перед запуском новой версии
примените имеющиеся миграции:

```sh
docker compose build web
docker compose run --rm web python manage.py migrate
docker compose up -d web
```

## Остановка и диагностика

```sh
docker compose ps
docker compose logs --tail=100 web db
docker compose stop
```

Для удаления контейнеров и сети, но **с сохранением базы**:

```sh
docker compose down
```

Данные PostgreSQL хранятся в постоянном volume `postgres_data`. Не используйте
`docker compose down -v`, если хотите сохранить материалы и администратора.
Volume не заменяет резервную копию. Переменные `POSTGRES_USER`, `POSTGRES_DB`
и `POSTGRES_PASSWORD` инициализируют PostgreSQL только при первом создании базы:
простое изменение пароля в `.env` не меняет пароль в существующей базе.

## Структура

- `config/` — настройки Django и корневые маршруты;
- `study/models.py`, `study/migrations/` — предметы, карточки и миграции;
- `study/importing.py`, `study/management/commands/import_cards.py` — проверка и импорт;
- `study/views.py`, `study/templates/`, `study/static/` — страницы и оформление;
- `data/questions.json` — 20 исходных подготовленных карточек, без изменений;
- `data/source/` — оригинальный PDF, не включается в Docker-образ;
- `AGENTS.md`, `.opencode/`, `opencode.json` — существующие инструкции и настройки
  инструментов разработки, не участвуют в работе сайта и не изменены.
